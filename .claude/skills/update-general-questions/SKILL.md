# 代表質問データ更新（general_questions）

札幌市議会の会議録検索システムから本会議録の全文を取得し、代表質問を質問者ごとに分けて AI で要約し、`general_questions` に取り込む。

UI設計・カテゴリ分類・品質基準は `general-questions` スキルを必ず併読すること。

> 福岡市版（upstream）の同名スキルを札幌市向けに書き換えたもの。福岡市の会議録システム（dbsr.jp）とは仕組みが別物なので、福岡市版の手順は使えない。

## 前提: 札幌市の本会議は「代表質問」

- 令和7年の第1〜4回定例会の本会議録を全日程確認したところ、**「一般質問」は一度も出てこず、質問はすべて代表質問**だった（会派を代表して市政全般を質問する形式）
- `general_questions` テーブルと web の画面は福岡市版由来で「一般質問」と表記しているが、札幌市では代表質問を入れる。画面の文言をどうするかは別途ユーザーと決める
- 代表質問は特定の議案に紐づかない。**`bill_discussions` に入れない**（全議案に紐付けていた旧スクレイパーの設計は誤データの原因になり、削除済み。`e8f9537`）

## データソース（会議録検索システム）

- トップ: https://sapporo.gijiroku.com/voices/
- CGI: `https://sapporo.gijiroku.com/voices/CGI/voiweb.exe`
- 文字コードは **Shift_JIS**。`iconv -f cp932 -t utf-8` で変換する
- リクエストの間隔は1〜2秒空ける

### ① 会議一覧（本会議）

```bash
curl -s -A "Mozilla/5.0" \
  "https://sapporo.gijiroku.com/voices/CGI/voiweb.exe?ACT=100&KGTP=1&FYY=2025&TYY=2025" \
  | iconv -f cp932 -t utf-8 > list.html
```

- `KGTP=1` が本会議、`FYY` / `TYY` は**西暦の暦年**（年度ではない。`FYY=2025` で令和7年の第1〜4回定例会が出る）
- 1会議日につき1行で、`FINO={数値}` のリンクとラベル（例: `令和 ７年第 ２回定例会, 05月29日-02号`）が付く。各会期の先頭に「目次」の行もある
- **会議録の公開には時間がかかる**。2026-09-21 時点では「本会議録の閲覧」の最新は令和7年で、令和8年（2026年）分は `FYY=2026` でも0件だった。取り込みたい会期の会議録がまだ公開されていないときは、ユーザーに伝えて待つ

### ② 本文

```bash
curl -s -A "Mozilla/5.0" \
  "https://sapporo.gijiroku.com/voices/CGI/voiweb.exe?ACT=203&KENSAKU=0&KGTP=1&FYY=2025&TYY=2025&FINO=4578&HESSION=1&HUID=0&KESSION=202502&HMODE=0" \
  | iconv -f cp932 -t utf-8 > day.html
```

- 上のパラメータで令和7年の各日の本文を取得できた（削除した旧スクレイパーと同じ形）。`FINO` と `FYY` / `TYY` だけを差し替える
- HTML の `<br>` を改行にし、タグを除去してテキスト化する
- 冒頭に `札　幌　市　議　会　会　議　録　（　第　２　号　）` と開催日（`令和７年（2025年）５月29日（木曜日）`）が入る。取得した本文が狙った日か、ここで確認する

## 日程の見分け方

| 号 | 内容 | 扱い |
|---|---|---|
| 目次 | 目次 | 対象外 |
| 01号 | 開会・議案の提出・提案説明・委員会付託 | 対象外 |
| 02号〜（令和7年は各定例会2〜3日） | **代表質問** | 取込対象 |
| それ以降 | 追加議案・委員長報告・討論・採決 | 対象外 |

- 代表質問の日は本文に「代表質問を続行します。」などの語が出る
- **02号の冒頭には先に議決する議案の委員長報告が入る**（例: `◆あおいひろみ議員　財政市民委員会に付託されました議案第３号…`）。これは代表質問ではないので除く
- 迷う日はユーザーに確認する

## 発言者の見分け方

行頭の記号で役割が分かる（福岡市版と違い、記号で区別されている）。

| 記号 | 役割 | 例 |
|---|---|---|
| `◆` | 質問者（議員） | `◆山田一郎議員　私は、ただいまから、自由民主党議員会を代表し、…` |
| `◎` | 答弁者（市長・副市長・教育長・局長など） | `◎市長（秋元克広）`、`◎総務局長（中澤伸之）` |
| `○` | 議長・副議長（進行） | `○議長（長内直也）`、`○副議長（村上ゆうこ）` |

- 質問者名は `◆` のあとの「〜議員」の前まで。**議席番号は会議録に出ない**ので `questioner_number` は null
- 会派は代表質問の冒頭「〜を代表し」から取る。会議録は正式名称（例: 自由民主党議員会）で書かれている。`questioner_party` は画面に表示するだけの文字列なので、`factions.display_name`（例: 自由民主党）にそろえる（dev のモックデータもこの形）。正式名称との対応は https://www.city.sapporo.jp/gikai/html/shingikekka.html の「会派名の略称」の表で確認する
- 1質問者 = 1レコード。代表質問の開始（`◆…を代表し`）から次の質問者の代表質問の開始までを1ブロックとする。同じ議員の2回目の `◆`（「ご答弁、ありがとうございました」など）は再質問なので同じブロックに含める
- 答弁者はブロック内の `◎` 行から取る。複数いれば `answerer_role` に「市長（氏名）・副市長（氏名）」の形でまとめる

## DBマッピング（general_questions）

| フィールド | 内容 |
|---|---|
| `council_session_id` | 会期ID（slug は `r7-2` 形式） |
| `session_day` | 会議録の号数（02号 → 2） |
| `question_order` | その日の中での質問順 |
| `questioner_name` / `questioner_number` / `questioner_party` | 質問者名 / null / 会派（上記） |
| `raw_text` | 原文（その質問者の質問・再質問と答弁の全文） |
| `summary` | 全体の要約 |
| `topics` | トピック配列（下記JSON） |
| `source_url` | 扱いは未決。`FINO` 付きのURLは今回の調査で再取得できたが、リンクとして恒久的に使えるかは未確認なので、ユーザーに確認する |
| `publish_status` | 取込時 `draft` → 確認後 `published` |

### topics の JSON 形（`GeneralQuestionTopic`）

```json
{
  "title": "…",
  "question_summary": "…",
  "answer_summary": "…",
  "answerer_role": "市長（氏名）・保健福祉局長（氏名）",
  "answerer_name": "",
  "block_summary": null
}
```

代表質問は1人で多くの項目を質問し、答弁を複数の答弁者が分担する。例: `◎市長（秋元克広）　全体で９項目にわたり、ご質問いただきました。…` のあとに `◎副市長（天野周治）　私からは、大きな７項目め、…`、`◎教育長（山根直樹）　私からは、６項目めの…` と続く。**どの項目にどの答弁者が答えたかを項目ごとに照合し、別の項目の答弁者を混ぜない**。

## 品質基準（要約するときに必ず守る）

`general-questions` スキルの詳細を参照。要点:

- **タイトル**: 会議録にある行政用語・略語はそのまま使う。カテゴリ分類はタイトルのキーワードで決まる（`build-topic-groups.ts` の `CATEGORY_MAP`）ので、キーワードを含めないと「その他」に落ちる
- **Qサマリーの文体**: 「質した」「問いただした」は使わない。「確認した」「求めた」「質問した」を使う
- **複数の答弁者**: `answerer_role` に「役職（氏名）・役職（氏名）」の形でまとめ、`answerer_name` は空にする
- 中国語簡体字・繁体字の混入をチェックする（例: 议・务・该）

## 手順

1. 会議一覧（`ACT=100`）で、対象の定例会の各日の `FINO` を特定する。会議録が未公開なら止めてユーザーに伝える
2. 対象の定例会の全日程の本文を取得する。保存先（リポジトリにコミットするか）はユーザーに確認する（福岡市版は `docs/fukuoka/meeting-minutes/` にコミットしていた）
3. 代表質問の日を見分け、委員長報告を除いて質問者ごとに分ける
4. AI で要約（summary + topics）を作る
5. **ユーザーレビュー（必須）**: 生成内容を提示し、承認を得てから書き込む（CLAUDE.md「AI生成コンテンツのDB更新ルール」）
6. `publish_status: draft` で登録する。`general_questions` には管理画面が無いので、REST または SQL で書き込む。接続は `db-access` スキルの規約に従うが、北海道版の本番DBは未確定（VPS 移行待ち）で `db-access` の記載は福岡市版のまま。**書き込み先は必ずユーザーに確認する**
7. web で表示を確認する（`/sessions/[session_slug]/questions` のテーマ別ビューでカテゴリ分類も目で確認、`/questions/[id]` で要約と原文の切り替えを確認）
8. 確認後、会期単位で `published` にする

トップページのバナーは最新の公開済みの会期を自動で拾うので、追加作業は不要。
