# 議案データ更新（bills / bill_contents / faction_stances）

札幌市議会の「議案等一覧」と「本会議の結果（審議結果PDF）」を一次ソースとして、議案・議決結果・会派別賛否・市民向け解説を登録する。

**登録は原案PDFを人が確認し、管理画面から行う**。スクレイパー（`packages/seed/sapporo/`）は誤データの原因になったため削除済み（`e8f9537`）。Claude の役割は PDF の読み取り補助・入力内容の下書き・解説文の生成とセルフレビューまでとし、DB への自動一括投入はしない。

> 福岡市版（upstream）の同名スキルを札幌市向けに書き換えたもの。福岡市版にあった「スクレイピング → REST で本番に upsert」の手順は採らない。

## データソース

| 用途 | URL | 備考 |
|---|---|---|
| 議案等一覧（最新の定例会） | https://www.city.sapporo.jp/gikai/html/giantouichiran.html | 番号・件名（原案PDFリンク）・本会議提出日・議決日・結果 |
| 議案等一覧（過去の会期） | `https://www.city.sapporo.jp/gikai/html/giantouichiran{令和2桁}{回2桁}{t\|r}.html` | 例: `giantouichiran0802t.html`（令和8年第2回定例会）、`giantouichiran0801r.html`（第1回臨時会）。最新の定例会は `giantouichiran.html` にしか載っていない |
| 原案PDF | 議案等一覧の件名リンク | 例: `/gikai/html/documents/08_3t_g01.pdf`（議案）、`08_3t_h01.pdf`（報告）。URLは推測せず必ずリンクから取る |
| 本会議の結果（審議結果PDF） | https://www.city.sapporo.jp/gikai/html/shingikekka.html | 会期ごとの「議決事件等一覧表」（例: `documents/08_kekka2t.pdf`）。付託委員会・委員会の結果・本会議の議決日と結果・反対会派の注記が載る。**会期終了後に掲載** |
| 会派名の略称 | 同ページ下部「会派名の略称」 | 審議結果PDFの注記（「（共反対）」等）を読むための対応表 |
| 会派別名簿 / 委員会別名簿 | https://www.city.sapporo.jp/gikai/meibo/meibo-kaiha.html / https://www.city.sapporo.jp/gikai/meibo/meibo-iinkai.html | 会派・委員会マスタとの突合に使う |
| 会議日程 | https://www.city.sapporo.jp/gikai/html/kaiginittei.html | 会期の開始日・終了日 |

- アクセスは1件ずつ、1〜2秒の間隔を置く
- PDFのテキスト抽出は `pdftotext -layout`（poppler-utils）を使う。未導入ならユーザーに導入を依頼する
- **審議結果PDFはテキスト抽出すると表の列が崩れる**（件名・日付・委員会名・注記が別々の行に散る）。注記がどの議案のどの欄に付いているかは PDF 原本を目で見て確認する

## 対象範囲（会期ごとにユーザーに確認）

どの種別まで登録するかは確定していない。登録を始める前に、対象の種別をユーザーに確認する。

参考として、令和8年第2回定例会の審議結果PDFの件数は、議案22・諮問2・意見書4・決議1・陳情90・報告11（ほか監査報告2）だった。陳情は件数が多い（`docs/20260531_1000_修正箇所一覧.md` では「可視化価値あり・未着手」の扱い）。

## 登録前に決めること（未決事項）

`docs/20260912_1528_プロジェクト方針とやりたいこと整理.md` §10 に挙がっている論点。**勝手に決めず、ユーザーに確認してから登録する**。

1. **決算特別委員会が `committees` マスタに無い**（第3回定例会の決算議案の付託先）。seed の委員会は常任委員会6つ・議会運営委員会・調査特別委員会3つのみで、予算特別委員会も無い
2. **補正予算は複数の常任委員会に分割付託される**が、`bills.committee_id` は1つしか持てない（例: 令和8年第2回の議案第1号は、総務・財政市民・文教・厚生・建設・経済観光の6委員会に付託）
3. **決算の「認定」を `status` のどれに当てるか**（同意・承認・諮問の答申も同じ問題）

## DBマッピング

### council_sessions（管理画面 `/council-sessions`）

| フィールド | 内容 |
|---|---|
| `slug` | `r{令和の年}-{回}`（例: `r8-3` = 令和8年第3回定例会）。臨時会の規則は未定なのでユーザーに確認する |
| `name` | 既存データの形式に合わせる（例: 「令和8年 第2回定例会（5・6月）」） |
| `start_date` / `end_date` | 会議日程・審議結果PDFの会期 |
| `council_url` | その会期の議案等一覧ページ。最新の会期は `giantouichiran.html` だが、会期が終わると過去ページ（`giantouichiran0803t.html` 等）に移るので、移ったら更新する |
| `is_active` | トップに出す会期（同時に1つだけ） |

### bills（管理画面 `/bills/new`・`/bills/[id]/edit`）

| フォーム項目 | 内容 |
|---|---|
| 議案番号 | 議案等一覧の表記どおり（例: 「議案第1号」「意見書案第1号」「陳情第253号～359号」） |
| 議案種別 | 下表 |
| 議案名 | 件名。リンク文字列末尾の「（PDF：478KB）」は含めない |
| 出典URL（議案原文） | 原案PDFの絶対URL |
| ステータス / ステータス備考 | 下表 |
| 公開日時 | サービス上の公開日時（既存データに合わせる） |
| 委員会 | 付託委員会（未決事項 1・2 に注意） |
| 定例会 | 対象の会期 |

- 一意制約は `(council_session_id, bill_number, bill_type)`（`bill_number` が空のときは対象外）。同じ会期で番号と種別の組が重複すると登録できない
- `status_order`・`publish_status_order` は生成列なので設定しない
- 登録時は `publish_status: draft`。解説とあわせてユーザーが確認してから `published` にする

#### 議案種別（`bill_type`）

| 札幌市の区分 | `bill_type` | 判定の目安 |
|---|---|---|
| 議案（条例・予算・補正予算・契約・財産・市道認定・損害賠償など） | `bill` | 番号が「議案」で、下の3つに当たらないもの |
| 議案のうち決算 | `bill_settlement` | 件名が「〜決算認定の件」 |
| 議案のうち人事 | `bill_personnel` | 件名が「〜任命に関する件」「〜推薦に関する件」など（結果は「同意」） |
| 議案のうち専決処分の承認 | `bill_ratification` | 専決処分の承認を求めるもの |
| 議員提出議案 | `member_bill` | 意見書案・決議案以外の議員提出の議案 |
| 意見書案 | `opinion` | 番号が「意見書案」 |
| 決議案 | `resolution` | 番号が「決議案」 |
| 諮問 | `consultation` | 番号が「諮問」 |
| 請願 | `petition` | 番号が「請願」 |
| 陳情 | `appeal` | 番号が「陳情」 |
| 報告 | `report` | 番号が「報告」（健全化判断比率報告・専決処分報告など。採決なし） |

#### 結果（`status` / `status_note`）

| 結果欄の表記 | `status` | `status_note` |
|---|---|---|
| （会期中・未議決） | `submitted`（付託後は `in_committee`） | null |
| 可決 | `approved` | null |
| 否決 | `rejected` | null |
| 採択 | `adopted` | null |
| 趣旨採択 | `partially_adopted` | null |
| 不採択 | `rejected` | null |
| 継続審査 | `in_committee` | 「継続審査」（`bill_status_enum` に継続審査の値が無いため） |
| 報告 | `reported` | null |
| 認定・同意・承認、諮問の答申（「〜を適当と認める」等） | **未決事項 3**。原文を `status_note` に残す案を提示し、ユーザーに確認する | |

- 文字列で判定するときは**「不採択」を「採択」より先に判定する**（部分一致で不採択が採択扱いになるバグが福岡市版であった）
- 継続審査になった議案の会期の扱い（最新の会期に付け替えるか）はユーザーに確認する

### faction_stances（管理画面 `/bills/[id]/edit` の会派賛否）

札幌市の審議結果PDFは会派ごとの○×表ではない。**反対した会派だけを略称で注記する方式**になっている（例: 「（共反対）」「（坂反対）」）。

- 注記の無い議案は全会一致として扱う
- 注記がどの欄（委員会の結果か、本会議の結果か）に付いているかを PDF 原本で確認する。本会議の採決をどう反映するかをユーザーに確認してから入力する
- 賛成・反対以外の注記（退席など）や、会派内で賛否が分かれた記載があれば、その都度ユーザーに確認する
- 意見書案などの「提出者」欄（例: 「民主市民連合、公明党及び日本共産党所属議員全員並びに…」）は提出者であって賛否ではない。混同しない

略称と `factions.name` の対応（seed `packages/seed/main/data.ts` と、shingikekka.html の略称表〈令和7年8月1日現在〉による）:

| 略称 | 会派 | `factions.name` |
|---|---|---|
| 自 | 自由民主党 | `jimin-sapporo` |
| 民 | 民主市民連合 | `minshu-shimin-sapporo` |
| 公 | 公明党 | `komei-sapporo` |
| 共 | 日本共産党 | `kyosan-sapporo` |
| 坂 | 坂元・荒井 | `sakamoto-arai-sapporo` |
| かずさ | 山口かずさ | `yamaguchi-kazusa-sapporo` |
| 未来 | 未来さっぽろ | `mirai-sapporo` |
| 健康 | 健康さっぽろ | `kenko-sapporo` |
| 大地 | 大地さっぽろ | `daichi-sapporo` |
| 市民ネ | 市民ネットワーク北海道 | `shimin-network-sapporo` |
| 維 | 日本維新の会 | `ishin-sapporo` |

会派構成は改選や結成・解散で変わる。新しい会期で初めて入力するときは、略称表・会派別名簿と `factions` テーブルを突合する。

### bill_contents（管理画面 `/bills/[id]/contents/edit`）

1議案につき `normal`（やさしい解説）と `hard`（詳しい解説）の2件。`title` は公式名称とは別のわかりやすいタイトル、`summary` は1〜2文、`content` は Markdown。書式は既存の解説に合わせる。

- **原案PDFの本文から作る**。議案名だけから生成しない（削除したスクレイパーの失敗要因）
- 原案PDFの読みどころ: 条例案は「（理 由）」欄と新旧対照表、契約・財産は「記」以下の項目。予算・補正予算は数値表がテキスト抽出で崩れやすいので、金額は PDF 原本で照合する
- 読み取れない場合は、公式の件名と結果だけで作り、手で補うようユーザーに伝える

## 手順

1. **会期の確認・作成**: `/council-sessions` に対象の会期があるか確認し、無ければ作成する
2. **既存登録の確認**: `/bills` で対象の会期の登録済み議案を確認し、二重登録を防ぐ
3. **一覧の作成**: 議案等一覧から番号・件名・原案PDFのURL・提出日を抜き出す。対象範囲と未決事項をユーザーに確認する
4. **原案PDFの読み取り**: 議案種別を判定し、解説の材料を抜き出す
5. **解説の生成**: normal / hard を作る
6. **ユーザーレビュー（必須）**: 登録内容と解説を提示し、承認を得てから登録する。チェック観点は CLAUDE.md「AI生成コンテンツのDB更新ルール」（日本語の自然さ・ソースとの整合・中国語漢字の混入）
7. **管理画面で登録**: `draft` で登録し、解説を入力する
8. **会期終了後の反映**: 審議結果PDFで結果・付託委員会・反対会派を確認し、ステータスと会派賛否を更新する
9. **検証**: 審議結果PDF冒頭の議決件数の内訳と登録件数を突合する。web の会期別議案一覧（`/sessions/[session_slug]/bills`）と議案詳細で表示を確認する
10. **公開**: ユーザーの確認後に `published` にする

## 注意

- 管理画面の「AI情報収集」（`/ai-collection`、ローカル専用）は Claude CLI の WebSearch / WebFetch で下書きを作る機能。プロンプトは「PDFは表形式で会派ごとの賛否」という前提で、札幌市の注記方式とは合わない。使う場合も下書きとして扱い、原案PDF・審議結果PDFと1件ずつ突合する
- 管理画面を使わずに REST や SQL で書き込む場合は `db-access` スキルの規約に従う。ただし北海道版の本番DBは VPS 移行（方針ドキュメント 塊B）で決まる予定で、`db-access` の接続先は福岡市版の記載のまま更新されていない。**接続先は必ずユーザーに確認する**
