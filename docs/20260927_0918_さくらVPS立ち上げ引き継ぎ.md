### 2-2. DNS：委任先とゾーンの置き場所が食い違っている

`ezocivic.tech` は**名前解決が一切できない**状態（ゾーンごと SERVFAIL）。原因は委任先の食い違い。

```
.tech レジストリが持つ委任先   : ns1〜ns5.xserver.jp      ← ゾーンが無い（REFUSED）
実際にゾーンがあるネームサーバー: ns1〜ns3.xdomain.ne.jp   ← A レコード3本とも正しい
```

確認した内容:

- ドメインは登録済み（2026-09-17 取得 / 2027-09-17 期限、status: client transfer prohibited）
- `ns1.xdomain.ne.jp` に直接聞くと、`gikai` / `gikai-admin` / `db` の3本とも `153.127.41.244` を正しく返す
- `ns1.xserver.jp` に聞くと **REFUSED**。REFUSED は「そのゾーンを持っていない」という応答なので、
  xserver.jp 側には**編集対象のレコードが1本も無い**（中身が違うのではなく、ゾーンごと無い）
- ゾーン内の NS レコード・SOA も `xdomain.ne.jp` を指しており、レジストリの委任先と食い違っている

Xserver にはネームサーバーが2系統あり、これを取り違えている:

| ネームサーバー | 用途 | ゾーンを置く条件 |
|---|---|---|
| `ns1〜5.xserver.jp` | エックスサーバー**レンタルサーバー**用 | レンタルサーバーの契約＋サーバーパネルでの「ドメイン設定追加」 |
| `ns1〜3.xdomain.ne.jp` | **Xserverドメイン**（ドメイン単体）の無料DNS | ドメインを持っているだけで使える |

**対応（人）**: Xserverアカウント → ドメイン → `ezocivic.tech` → ネームサーバー設定を
`ns1.xdomain.ne.jp` / `ns2.xdomain.ne.jp` / `ns3.xdomain.ne.jp` に変更する。**レコードは触らない**。

> レンタルサーバー側にゾーンを作る道（委任先を変えず xserver.jp にレコードを入れる）も、
> **レンタルサーバーを契約していれば**可能。ただし (1) 正しいレコードが既に xdomain 側にある、
> (2) ドメイン設定追加でレンタルサーバーの IP を向いた A レコードが自動生成され上書きの手間と事故が増える、
> (3) 使っていないレンタルサーバーに DNS が依存する、の3点から**委任先を変える方を選んだ**。
> **レンタルサーバー契約の有無は未確認**（§7 参照）。

反映確認:

```bash
nslookup -type=A gikai.ezocivic.tech 8.8.8.8
```

## 4. レビューで見つけた問題と対応

### 4-1. 会話ログがバックアップに最大14日残る（#54 で対応済み）

`pg_dump -n public` は `public.chat_logs` を含み、バックアップは14日保持する。
つまり DB から90日で消した会話ログが**バックアップの中に最大14日生き延び**、
プライバシーポリシー文案の「AI チャットのやり取りは 90 日で自動的に削除します」と食い違う。

**対応**: `pg_dump` から `-T public.chat_logs` で除外した。

- `chat_logs` を参照する外部キーが無いことを確認済み（`chat_logs` 側が `prompt_versions` を参照するのみ）。
  除外しても復元時に他テーブルへ影響しない
- **復元しても会話ログは戻らない**。分析用の一時データなので戻せなくてよい、という判断
- これにより**プライバシーポリシーの文言を修正せずに済む**

### 4-2. トピック分析が公開前の VPS で 401 になる（#56 で対応）

admin のトピック分析は Server Action / API route から **admin 自身を HTTP で呼ぶ**作り。

```
run-topic-analysis-action.ts  → ${NEXT_PUBLIC_APP_URL}/api/topic-analysis/run
trigger-next-phase.ts         → ${NEXT_PUBLIC_APP_URL}/api/topic-analysis/phases/phase{1,2,3}
```

公開前は nginx が admin の全パスに Basic 認証をかけるため、この**サーバー間 fetch は 401 で弾かれ、
解析が1フェーズも進まない**。確認した点:

- `ADMIN_ENABLE_CLAUDE_CLI`（PR #46）では塞がれていない。トピック分析は Claude CLI を使わない機能で、
  `/bills/[id]/topic-analysis` は `requirePageAccess` だけのガード。**VPS の管理画面にも出る**
- `NEXT_PUBLIC_*` はビルド時に JS へ埋め込まれるため、VPS の env ファイルでは差し替えられない
- 手順書 §6 #3 が admin → web だけを対象にしていたため漏れていた

**対応**: `ADMIN_INTERNAL_URL` を追加し、設定されていればそちらを優先（#51 と同型）。
