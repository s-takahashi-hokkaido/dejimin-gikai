# 公開までのタスク分割（複数セッション並行用）

- 作成: 2026-09-23
- 目的: [プロジェクト方針とやりたいこと整理](20260912_1528_プロジェクト方針とやりたいこと整理.md) §10 の残作業を、**1タスク＝1セッション（＝1 worktree・1 PR）**の単位に切り分ける。セッションを並べて同時に進めるときに、衝突しない組み合わせが一目でわかるようにする
- 位置づけ: 何をやるか・なぜやるかの正本は方針ドキュメントのまま。このドキュメントは「どう分けて進めるか」だけを持つ

---

## 0. 使い方

### セッションの始め方

新しいセッションには次のように頼む。

> `docs/20260923_1740_公開までのタスク分割.md` のタスク **T3** をやって

そのセッションは次の順で進める。

1. このドキュメントの該当タスクと、「読むもの」に挙げたドキュメントを読む
2. 「先に決めること」が残っていたら、**着手前にユーザーへ確認する**
3. CLAUDE.md の手順どおり worktree を作る（ブランチ名は各タスクの「ブランチ」欄）
4. 作業 → `pnpm lint` / `pnpm typecheck` / `pnpm test` → PR（base は `develop`）→ `/review`
5. **同じ PR の中で、このドキュメントの該当タスクの「状態」行を更新する**

### 状態の書き方

各タスクの「状態」行だけを書き換える。表にまとめないのは、複数の PR が隣り合う行を同時に書き換えてコンフリクトするのを避けるため。

- `未着手` / `進行中（PR #xx）` / `完了（PR #xx, YYYY-MM-DD）` / `保留（理由）`

### 人手が要るタスク

「種類」が **人** のタスクは、契約・相談・目視確認など Claude だけでは完結しないもの。Claude は下調べと手順書づくりまで担当する。

### T5. Langfuse を自前の DB に移す

- 状態: 未着手
- 種類: 設計＋コード（マイグレーションあり）
- ブランチ: `feat/langfuse-to-db`（大きければ下の 5-1〜5-3 で PR を分けてよい。例: `feat/prompts-in-db`・`feat/save-chat-logs`・`chore/remove-langfuse`）
- 読むもの: 方針ドキュメント §5 ④（2026-09-23 改訂の決定と、落とすもの・残すものの表）
- 方針: Langfuse は外すが、**機能は落とさない**。プロンプトの無デプロイ編集と会話ログを自前の DB に移す
- 前提作業: Langfuse 上の**現行プロンプト本文**（`top-chat-system` / `bill-chat-system-normal` / `bill-chat-system-hard`）を書き出す。
  Langfuse の認証情報が要るので、ユーザーに取得を頼む。**撤去の前に済ませないとプロンプトが失われる**
- 先に決めること（着手前に案を出してユーザーへ確認する）:
  1. `prompts` の履歴の持ち方 — 案A: 1テーブルで上書き（履歴は T8 の監査ログに任せる）／案B: `prompt_versions` に追記し、有効な版を指す
  2. 会話ログの保存期間（無期限／N日で削除）と、admin での閲覧画面を作るか（SQL で見るだけで足りるか）
  3. `interview_sessions.langfuse_session_id` カラムを消すか残すか

#### 5-1. プロンプトを DB に移す

- `prompts` テーブルのマイグレーション（RLS 有効・ポリシーなし。CLAUDE.md のルールどおり）。前提作業で書き出した本文を初期データとして入れる
- `web/src/lib/prompt/` に DB から取得する `PromptProvider` を足し、`createPromptProvider()` を差し替える。
  変数の埋め込み（`{{billName}}` など）は既存の純粋関数 `shared/compile-prompt.ts` を使い回す
- admin にプロンプトの一覧・編集画面を作る（**admin ロールのみ**。権限設計 §4 に行を足す）
- 完了条件: admin で書き換えたプロンプトが、デプロイなしでトップ・議案の AI チャットに効く

#### 5-2. AI チャットの会話を DB に保存する

- 今の `chats` テーブルはコードから使われておらず、`bill_id` が NOT NULL なのでトップのチャットを入れられない。
  マイグレーションで作り直す（`bill_id` を NULL 可に、`session_id`・`page_type`・`prompt_name` を足す など）
- `handle-chat-request.ts` の `onFinish` で、**最新のユーザーの発言1件と、今回の AI の応答**を保存する（保存の失敗でチャットを止めない。`recordChatUsage` と同じ扱い）
  - ブラウザは毎回それまでの会話を全部送ってくるので、`messages` を全部保存すると過去のやりとりが毎回重複して入る
- 完了条件: トップ・議案・予算の各チャットの会話が DB に残る

#### 5-3. Langfuse を外す

- `web/src/lib/prompt/langfuse/`、web / admin の `lib/telemetry/register.ts` の Langfuse exporter、
  `experimental_telemetry` の Langfuse 向けメタデータ、`langfuse` / `langfuse-vercel` パッケージ、`LANGFUSE_*` 環境変数（`.env.example` 含む）を削除する
- LLM 呼び出しがエラーになった時は、入出力をサーバーログに出す（トレースの代わり）
  - ストリーミング中のエラーは `streamText` を囲む `try/catch` では捕まらない。**`streamText` の `onError`** で出す
  - ログに出す入力は市民の発言そのもの。サーバーログの保存期間と閲覧できる人を T7（VPS 構築）で決め、会話ログと同じくプライバシーポリシー（T2）の対象にする
- 完了条件: `LANGFUSE_*` を設定しなくても、チャットとインタビューがローカルで動く

#### 注意

- 会話ログを保存し始めることは、**プライバシーポリシー（T2）に書く**必要がある。保存期間もあわせて書く
- 会話ログには市民の入力がそのまま入る。扱いは `db-access` スキルに従う
- **T4・T8 とマージの順番を合わせる**（§1）
