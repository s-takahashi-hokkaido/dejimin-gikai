# 公開までのタスク分割（複数セッション並行用）

- 作成: 2026-09-23
- 目的: [プロジェクト方針とやりたいこと整理](20260912_1528_プロジェクト方針とやりたいこと整理.md) §10 の残作業を、**1タスク＝1セッション（＝1 worktree・1 PR）**の単位に切り分ける。セッションを並べて同時に進めるときに、衝突しない組み合わせが一目でわかるようにする
- 位置づけ: 何をやるか・なぜやるかの正本は方針ドキュメントのまま。このドキュメントは「どう分けて進めるか」だけを持つ

---

## 0. 使い方

### セッションの始め方

新しいセッションには次のように頼む。

> `docs/20260923_1740_公開までのタスク分割.md` のタスク **T11** をやって

そのセッションは次の順で進める。

1. このドキュメントの該当タスクと、「読むもの」に挙げたドキュメントを読む
2. 「先に決めること」が残っていたら、**着手前にユーザーへ確認する**
3. CLAUDE.md の手順どおり worktree を作る（ブランチ名は各タスクの「ブランチ」欄）
4. 作業 → `pnpm lint` / `pnpm typecheck` / `pnpm test` → PR（base は `develop`）→ `/review`
5. **同じ PR の中で、このドキュメントの該当タスクの「状態」行を更新する**。完了したら、そのタスクの節（§2）を削除する。
   残作業があれば、関係するタスクか §進捗 の「持ち越し」に移す

### 状態の書き方

各タスクの PR では、そのタスクの「状態」行（§2）だけを書き換える。§進捗 の表は書き換えない。
表を各 PR で触ると、隣り合う行を同時に書き換えてコンフリクトするため。

- `未着手` / `進行中（PR #xx）` / `保留（理由）`
- 完了したタスクは記載を残さない（経緯は git の履歴と PR で追える）

§進捗 の表は**棚卸しの時だけ**まとめて更新する。棚卸しは「タスク分割の棚卸しをして」と頼む。
棚卸しでは「状態」行を鵜呑みにせず、PR の状態（`gh pr list --state all`）とコードの実物を見て判定し、ずれていれば「状態」行も直す。

### 人手が要るタスク

「種類」が **人** のタスクは、契約・相談・目視確認など Claude だけでは完結しないもの。Claude は下調べと手順書づくりまで担当する。

## 3. 公開までの最短経路

公開の条件は **T1・T2b・T7**。T4b（データ）は公開の価値に効くので、同じ時期に済ませる。
T10 は議員・出馬者に声を掛ける前までに済めばよい（目安は年明け。方針ドキュメント §10「期限の目安」）。

```
済み                : T3, T4, T5, T6, T8, T9, T11, T12（T2 は文案まで）
いま（並行）        : T2b（T7 待ちの2文を除く）, T4b ／ T1 はユーザー判断
次                  : T7（公開。T1・T2b の後）→ T2b の残り2文
最後                : T10（SMTP の後）
```
