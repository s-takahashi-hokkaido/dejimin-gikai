作成日: 2026-11-12

- 目的: 実装するセッションが、決めたことを抜け漏れなく実装するための確認表
- 使い方: [実装タスク分割](20261112_2019_AIインタビュー広場_実装タスク分割.md) の各タスクで、§1〜§4 を毎回使う。
  §5〜§7 は、最後のタスク（P12）でまとめて確認する
- §1〜§4 は確認用の手順であり、チェックを書き込まない（毎回使うため）。
  **チェックを書き込むのは §5〜§7 だけで、書き込むのは P12 の PR だけ**（各 PR で触るとコンフリクトするため）

## 1. 着手前

- [ ] タスク分割の §0・§1 と、自分のタスクの節を読んだ
- [ ] 自分のタスクの「読むもの」を読んだ
- [ ] 依存タスクの「状態」が `完了` になっている。なっていなければユーザーに確認する
- [ ] 仮決め（タスク分割 §1 の K1〜K9）のうち自分のタスクに影響するものを確認した。D1 が未完了なら、仮決めのまま進めてよいかユーザーに確認する
- [ ] GitHub 上の PR の状態を確認した（同じタスクの PR がすでに無いか、ブランチがマージ済みでないか）
- [ ] worktree を作った（CLAUDE.md の手順。クラウドのセッションで作業ブランチが指定されている場合はそれを使う）
- [ ] 自分のタスクの「やらないこと」を確認した。範囲を広げたくなったら、広げずに PR に書いて次のタスクへ渡す

## 2. 実装中（共通）

CLAUDE.md のルールのうち、広場の実装で特に踏みやすいもの。

**構成**

- [ ] `app/` 配下の `page.tsx` は、パラメータの受け渡しだけの薄いラッパーにした
- [ ] 実装は `features/` 配下に、server / client / shared の構成で置いた
- [ ] export 用の `index.ts` を作っていない
- [ ] Server 側のファイルに `"server-only"`、Client Component に `"use client"` を付けた
- [ ] ファイル名はケバブケース

**見た目**

- [ ] `<button>` を使わず、`@/components/ui/button` の `Button` を使った
- [ ] インライン SVG を使わず、`lucide-react` のアイコンを使った
- [ ] 色は `globals.css` のトークンを使った（`text-[#xxx]` などの直接指定をしていない）
- [ ] スマホ幅とデスクトップ幅の両方で崩れていない

**ロジックとテスト**

- [ ] 外部に依存しない判定・計算・変換は、純粋関数として `utils/` に切り出した
- [ ] 切り出した純粋関数に、同じ階層の `*.test.ts` がある
- [ ] `vi.mock` に頼っていない。Supabase はローカルの実物、LLM は差し替えでテストした

**データアクセスと認可**

- [ ] DB へのアクセスは repository に集約し、`createAdminClient()` 経由にした
- [ ] 認可は Server Action / Loader の先頭で行った。**画面のボタンを消すだけで済ませていない**
- [ ] admin の書き込みは `createAuditedAdminClient` を使い、変更履歴に実行者が残る

## 3. 種類別

### DB を変えるタスク

- [ ] 新しいテーブルに `enable row level security` を書いた。ポリシーは定義していない
- [ ] マイグレーション・再生成した型（`pnpm db:types:gen`）・`docs/schema/`（`pnpm db:docs`）を同じ PR に入れた
- [ ] `docs/schema/` を手で編集していない
- [ ] `pnpm db:reset` が最初から通る
- [ ] 制約（ユニーク・CHECK）が効くことを、結合テストで確かめた
- [ ] PR の本文に、スキーマの変更を明記した

### admin のタスク

- [ ] `can-access-page.ts` に新しいパスの権限を足した（足し忘れると運営者しか開けない）
- [ ] 議員・候補者が、**自分の議題以外**を操作できないことをテストした
- [ ] 機能フラグがオフのとき、ナビに出ず画面も開けない

### web のタスク

- [ ] `features.plaza` が `false` のとき、画面が 404 で入口も出ない
- [ ] 議題を出す画面には、必ず作成者（名前と会派、候補者はその旨）を出した
- [ ] 一覧の並び順に、人気順・新着順・回答数順を使っていない
- [ ] キャッシュを使う場合、オープン・クローズ・レポート完了・取り下げで更新される

### AI・プロンプトのタスク

- [ ] プロンプトの変更は、D3 の成果物に沿っている
- [ ] LLM の出力は、スキーマで検証している
- [ ] 議案向けの既存の挙動を変えていない
- [ ] 既存の AI 利用量の制限が、新しい経路にもかかっている

### cron・インフラのタスク

- [ ] 内部 API は認証が無いと拒否する
- [ ] 同じ処理を2回続けて呼んでも、二重に実行されない
- [ ] 構築手順のドキュメントを更新した

## 4. 完了前〜PR 後

**push の前**

- [ ] `pnpm lint` が通る
- [ ] `pnpm typecheck` が通る
- [ ] `pnpm test` が通る
- [ ] DB や結合テストに関わる変更なら、`pnpm test:integration` が通る
- [ ] 自分のタスクの「完了条件」をすべて確認し、タスク分割の該当節にチェックを付けた
- [ ] タスク分割の該当節の「状態」行を更新した（ほかのタスクの節は触っていない）
- [ ] GitHub 上の PR の状態をもう一度確認した

**PR**

- [ ] base は `develop`
- [ ] 本文に、範囲の概要・実行したテスト・スキーマや環境変数の変更を書いた
- [ ] 画面を変えたなら、スクリーンショットを貼った
- [ ] 範囲から外したこと・次のタスクへ渡すことを書いた

**PR の後**

- [ ] コンフリクトが無い
- [ ] CI が通った
- [ ] CodeRabbit のレビューを確認し、重要な指摘に対応した
- [ ] 対応したレビューコメントを resolve した
- [ ] `/review <PR番号>` でレビューを受け、指摘に対応した

## 6. 抜け道の確認

[設計思想](20261112_2009_AIインタビュー広場_設計思想.md) が塞ごうとしている抜け道が、実装で開いていないか。
**P12 で、画面だけでなく Server Action・API・SQL 関数も見て確認する。**

**途中経過が漏れていないか**（設計思想 2-5）

- [ ] オープン中の議題について、回答の中身・集計・個別レポートが、web のどの URL・API からも取れない
- [ ] オープン中の議題について、作成者が回答の中身を見られない（K1）
- [ ] 検索結果やサイトマップに、オープン中の議題の回答内容が含まれない

**議員が結果を操作できないか**（設計思想 2-5・2-6・2-7）

- [ ] レポートを作らない・止める・やり直す・隠す・書き換える手段が、作成者に無い
- [ ] クローズした議題を、オープンや下書きに戻す手段が無い
- [ ] 回答が始まった議題のタイトル・本文を変える手段が無い
- [ ] 回答が始まった議題を消す手段が無い
- [ ] アカウントの削除やロールの変更で、議題やレポートが消えない（K7）

**1人1つを回避できないか**（設計思想 2-3）

- [ ] 同時に操作しても、オープンは1つだけ
- [ ] 取り下げ・削除・ロール変更を組み合わせても、同時に2つオープンできない

**閉じた関心を再現していないか**（設計思想 2-4）

- [ ] 一覧・レポート一覧の既定の並び順が、ランダム以外になっている画面が無い
- [ ] 「人気の議題」「回答の多い議題」のような、偏りを強める表示を足していない
- [ ] 検索しないかぎり、特定の議員・会派の議題だけが並ぶ画面が無い

**記名が欠けていないか**（設計思想 2-2）

- [ ] 議題が出るすべての画面（一覧・詳細・レポート・レポート一覧・検索結果・共有時の表示）に、作成者が出ている

**他人の議題を操作できないか**

- [ ] 議員・候補者が、他人の議題の編集・削除・オープン・クローズを、Server Action の直接呼び出しでもできない
- [ ] 内部 API（自動クローズ・分析のフェーズ）が、認証なしで呼べない

**回答数の見せ方**（設計思想 2-9）

- [ ] 回答数不足のレポートが、不足の表示なしで読める画面が無い
- [ ] 回答が少ないことを理由に、レポートが非公開になる経路が無い

## 7. 通しの確認

**P12 で、ローカルで最初から最後まで実施する。** 機能フラグはオンにして行う。

**準備**

- [ ] `pnpm db:reset` で初期化した
- [ ] 議員A（会派あり）・議員B（別の会派）・候補者C・運営者のアカウントがある

**議題を出す（admin）**

- [ ] 議員A が下書きを作り、Markdown（見出し・箇条書き・表・リンク）で本文を書ける
- [ ] 議員A がオープンできる
- [ ] 議員A が2つ目をオープンしようとすると、拒否される
- [ ] 議員B・候補者C もそれぞれ1つオープンできる
- [ ] 議員B から、議員A の議題を編集・クローズできない
- [ ] 運営者は全員の議題を見られるが、作成はできない

**広場を見る（web）**

- [ ] ヘッダーから「AIインタビュー広場」に切り替えられ、「議会」に戻れる
- [ ] 一覧に3つの議題が出て、それぞれ作成者が表示されている
- [ ] 一覧を開き直すと、並び順が変わる
- [ ] ページを送っても、同じ議題が出ない（件数を増やして確認）
- [ ] 検索で、タイトル・本文・作成者名・会派名から絞り込める
- [ ] 議題詳細で、Markdown が議案詳細と同じ見た目で表示される

**回答する（web）**

- [ ] 開始前の説明に、回答が要約されて自動で公開されることが書いてある
- [ ] インタビューを最初から最後まで通せる
- [ ] 回答した後、議員A の議題は admin で編集も削除もできなくなっている
- [ ] 回答した後も、web からほかの人の回答や集計は見えない
- [ ] 議員A の admin には、回答数だけが出ている

**クローズとレポート**

- [ ] 議員A がクローズすると、確認ダイアログに「再オープン不可」「自動公開」が出る
- [ ] クローズすると、レポートの生成が自動で始まる
- [ ] 完了すると、web の議題詳細とレポート一覧にレポートが出る
- [ ] レポートに「立場を越えて一致している点」と「割れている点とその理由」がある
- [ ] 回答が10件未満なので、一覧に「回答数不足」のバッジ、本文の最上部に帯が出る
- [ ] クローズ後、議員A は次の議題をオープンできる
- [ ] クローズした議題を再オープンする手段が無い
- [ ] クローズ後は、その議題に回答できない

**境界**

- [ ] 回答0件でクローズすると、分析は走らず「回答なし」と出る
- [ ] 期限を過ぎた議題が、自動クローズの処理でクローズされ、レポートが作られる
- [ ] レポートの生成が失敗したとき、運営者が再実行できる
- [ ] 運営者が議題を取り下げると、web のどの画面にも出なくなる

**既存機能が壊れていないか**

- [ ] 議案のインタビューを最初から最後まで通せる
- [ ] 議案の論点分析を、admin から実行できる
- [ ] 議案詳細の Markdown 表示が変わっていない
- [ ] 既存の検索が動く
