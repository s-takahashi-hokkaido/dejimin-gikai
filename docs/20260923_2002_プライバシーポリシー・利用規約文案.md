## 1. 事実の整理（文案の前提）

文案を書く前に、コードとスキーマから「実際に何を取得し、どこへ送り、誰が読むか」を確認した。

### 1-1. 取得しているデータ

| データ | 保存先 | 個人情報を含みうるか | 備考 |
|---|---|---|---|
| インタビューの質問・回答の**全文** | `interview_messages.content` | **含みうる**（自由記述） | role（assistant/user）と本文をそのまま保存 |
| インタビューの**AI 要約・意見・スタンス・属性推定** | `interview_report`（`summary`・`opinions`・`stance`・`role`・`role_description`・`role_title`・`scores`） | **含みうる** | AI が「主婦」「物流業者」などの属性を**推論**して保存する |
| インタビューセッション | `interview_sessions`（`user_id`・`started_at`・`rating`） | 識別子 | `user_id` は匿名認証の UUID |
| 有識者登録 | `expert_registrations`（`name`・`affiliation`・`email`） | **明確に個人情報** | 氏名・所属・メールアドレスを直接取得している |
| AI 利用ログ | `chat_usage_events`（`user_id`・`model`・トークン数・コスト） | 識別子のみ | 本文は入っていない |
| レポートへのリアクション | `report_reactions`（`user_id`・`reaction_type`） | 識別子のみ | |
| **難易度設定の Cookie** | ブラウザ（`bill_difficulty_level`） | 含まない | 議案解説の難易度（ふつう／難しい）を覚えておくため。`httpOnly`・**保持期間 1 年**（`DIFFICULTY_COOKIE_OPTIONS`）。サーバーには保存しない |
| **匿名認証のセッション** | ブラウザの Cookie（`@supabase/ssr` の `createBrowserClient` の既定） | 識別子のみ | AI チャット・インタビューの `user_id` を保つ。**Cookie を拒否すると匿名ログインが保てず、`/api/chat`・`/api/interview/chat` が 401 を返して AI 機能が使えない** |
| **AI チャットの会話本文** | `chat_logs`（`user_id`・`session_id`・`page_type`・`bill_id`・`role`・`message`） | **含みうる** | 保存期間 90 日。`delete_expired_chat_logs()` で削除（**定期実行は T7 の未チェック項目**。migration のコメントも「定期実行は VPS の cron で行う（T7）」） |
| **LLM エラー時のサーバーログ** | サーバーの標準エラー出力 | **含みうる** | `handle-chat-request.ts` の `onError` と catch が **`userText`（市民の発言そのもの）** を `console.error` に出す。このためサーバーログも個人情報を含む保管場所になる |
| 管理画面の変更履歴 | `admin_audit_logs`（`actor_email`・`actor_role`・`actor_faction_id`・`before_data`・`after_data`） | **管理画面利用者の個人情報** | 対象は `bills`・`bill_contents`・`faction_stances` の3テーブルのみで、**市民のインタビュー内容は対象外**。**保持期間は無期限**（削除処理を作らない方針が migration に明記されている） |

### 1-2. 外部への送信先（ここが方針 §2 の「はみ出し」）

```
ブラウザ → 自前サーバー → OpenAI（米国）
```

> サーバー自体は T7 まで Vercel で動いている（「日本国内」と書けるのは T7 の後。§3）。

- 既定モデル: AI チャット = `gpt-4o`、AI インタビュー = `gpt-5-mini`、
  インタビューの要約・admin のトピック解析 = `gpt-5-mini`

プライバシーポリシー第5条の送信先は **OpenAI 1社のみ**と書いている。

### 1-4. 公開の経路

インタビュー結果が公開される経路は 2 つあり、**両方の合意が必要**（`interview_report` の
`is_public_by_user` と `is_public_by_admin` が別カラムになっている）。

- `is_public_by_user` — 回答者本人が公開に同意したか
- `is_public_by_admin` — 運営者が公開を許可したか

ただし運営者の確認（`is_public_by_admin`）を見ているのは一覧だけで、結果ページ `/report/[id]` と
全文ページ `/report/[id]/chat-log` は `is_public_by_user` だけで誰でも開ける。
プライバシーポリシー第7条はこの実態どおり「公開を許可すると URL を知る人が全文まで閲覧できる。一覧に載るのは運営者の確認後」と書いている。

### 1-6. どの情報が個人情報にあたるか（削除依頼の範囲）

> この節は事実の整理であって、法的な判断ではない。判断が要る点は §4 の未決事項6 と
> §5 の相談項目に出す。

**なぜ削除の窓口が要るのか — 理由は2つある。**

**理由1: 窓口を示すこと自体が法律上の要求。**
個人情報保護法は、保有個人データについて、**開示・訂正・利用停止等の請求に応じる手続と
苦情の申出先を、本人が知り得る状態に置く**ことを求めている（第32条）。
削除に応じるかどうかは場合によるが、**窓口を示さないという選択肢は無い**。

なお 2017 年の改正で「取扱件数 5000 件以下は適用除外」は廃止されているため、
個人運営であっても、反復継続して行う以上は対象になる。

**理由2: この企画の設計が「同意」に依存しているから。**
[権限設計 §4](20260912_1736_管理画面ロール権限設計.md) は、インタビューの生ログを全ロールに開く理由を
「アクセス制御ではなく**市民への事前告知と同意**でカバーする設計」と書いている。
アクセス制御をかけない代わりに同意で担保するなら、**同意が撤回できないと同意の実質が失われる**。
その撤回手段が削除依頼にあたる。こちらは法律というより、設計の一貫性の問題。

#### 項目ごとの該当性と、削除依頼の必要性

| 項目 | 個人情報にあたるか | 削除依頼の必要性 |
|---|---|---|
| `expert_registrations`（氏名・所属・メール） | **確実に該当** | **最も高い**。疑いの余地なく保有個人データ |
| `admin_audit_logs.actor_email` 等 | **確実に該当**（議員・出馬者・運営者の） | **高いが、無期限保持の決定と衝突する**（§4 の未決事項6） |
| `interview_messages`（発言の全文） | **内容次第**。本人が特定できる情報を書けば該当する | **高い**。上の理由2 がここに効く |
| `interview_report`（要約・意見・属性推定） | 同上。加えて AI が「主婦」「物流業者」等の属性を**推論して**保存している | **高い**。本人が言っていない属性が付くため |
| `chat_logs`（会話本文） | 内容次第 | **低い**。90 日で自動消滅する。行には匿名認証の `user_id` が入るが、本人がそれを示す手段が無く、どれが本人のものか特定できない |
| `chat_usage_events` | `user_id` は匿名認証の UUID、本文を含まない | **ほぼ不要** |
| サーバーログ（IP＋`userText`） | 照合次第 | 個別削除ではなく**保存期間の管理**で対応（T7） |

**結論**: 削除依頼が実際に効くのは **有識者登録** と **インタビュー（生ログ・レポート）** の2つ。
プライバシーポリシー 第9条はこの2つを念頭に書いている。

## 2. 書き方の方針

1. **できないことを約束しない**。「匿名化処理を行います」「厳重なセキュリティ」のような
   検証できない約束は書かず、実際にやっていることだけを書く
2. **主語を「当団体」から個人運営者に寄せる**。`siteConfig.operator.name` は `s.takahashi` で、
   団体ではない。文案では「運営者」を使う（表記は決定事項4 のとおり `s.takahashi`）
3. **はみ出しは隠さず書く**。LLM が国外に出ることは方針 §2 で織り込み済みの例外なので、
   詫びるのではなく**線引きの理由ごと**書く。これは発信材料でもある（方針 §1-4）
4. **難しい言い回しを避ける**。市民向けのサービスなので、法律文書の体裁より読めることを優先する

## 4. 未決事項（ユーザーの確認が必要）

### 未決事項6: 削除等のご依頼まわり

削除がなぜ必要か、どの項目に効くのかは §1-6 のとおり。
プライバシーポリシー 第9条は項目ごとに対応を書き分けている。

**6-a. 本人確認の方法 — これは決めてよい状態にある**

会員登録がないため、「どのやり取りがあなたのものか」を運営者が特定できない。
プライバシーポリシー 第9条では**結果ページの URL を知っていること**をもって本人とみなしている。

- URL が推測不能であることが前提。`interview_report.id` は `gen_random_uuid()` なので満たす
- **ただし本人が公開を許可した結果ページは、URL が他人に共有されうる**（§1-4）。
  URL を持つ他人が本人になりすまして削除を依頼できてしまう。公開済みのものは本人が結果ページで非公開に戻せるが、
  削除依頼の本人確認として URL だけで足りるかは要判断
- AI チャットには結果ページが無く個別特定ができないため、**個別の削除は受け付けない**と書いている。
  90 日で自動削除する前提（§3）
- 有識者登録は**登録時のメールアドレス**で本人確認できる

> **この3つで運用できるかの確認だけが残っている。**

**6-b. 監査ログと削除請求の衝突 — 未解決**

「監査ログは無期限で残す。アカウント削除後も当時のメールアドレスを残す」と決めている
（検証可能性のため。プライバシーポリシー 第11条）。一方で `admin_audit_logs.actor_email` は**明確な個人情報**であり、
議員・出馬者は本人にあたる。

**議員から「自分のメールアドレスを消してほしい」と言われた場合にどう答えるか**が決まっていない。

| 案 | 内容 | 備考 |
|---|---|---|
| 6b-A | **応じない**（正当な目的があり、事前に告知しているため） | 「アカウント発行時に案内する」（T10）が、この根拠を強くする方向に働く |
| 6b-B | メールアドレスだけ伏せ、`actor_user_id` と操作内容は残す | 「誰が」の追跡可能性は残るが、検証の実用性は落ちる |
| 6b-C | 応じる（行ごと削除する） | 監査ログの意味が失われる。**取らない** |

> **判断せず、§5 の相談項目に出す。** 記録を残す目的の正当性と告知の有無が評価に効く論点なので、
> 専門家の確認を経てから決める。

**6-c. 事業者の氏名・住所の公表 — 決定事項4 に関わる**

個人情報保護法 第32条は、公表すべき事項として**事業者の氏名（名称）と住所**を挙げている。
決定事項4（`s.takahashi` ＋ X アカウント）はこれを満たしていない可能性がある。

ただし同条は「**本人の知り得る状態（本人の求めに応じて遅滞なく回答する場合を含む）**」としており、
**サイトに住所を掲載する必要はなく、求められたら答えられればよい**という読み方ができる。

> **決定事項4 を覆す話ではない**が、「**聞かれたら本名と住所を回答する用意がある**」状態には
> しておく必要がある。この読み方で足りるかを §5 の相談項目に出す。

## 5. 並行してやる人手作業: 専門家への相談

### 5-A. 個人情報保護法について

§1-6・§4 の未決事項6 で出た論点。

1. **監査ログと削除請求**（§4 の 6-b）— 管理画面の変更履歴に実行者のメールアドレスを
   **無期限で**保存し、アカウント削除後も残す設計について、本人から削除を求められた場合に
   **応じない**ことは許されるか。目的（議案解説の変更履歴の検証可能性）の正当性と、
   アカウント発行時に告知していることは、判断にどう効くか
2. **事業者の氏名・住所の公表**（§4 の 6-c）— 個人運営の場合、第32条の公表事項を
   「求められたら回答する」形で満たせるか。サイトに本名・住所の掲載が必要か
3. **本人確認の方法** — 会員登録が無いサービスで、**結果ページの URL を知っていること**をもって
   本人からの削除依頼として扱うことに問題はないか
4. **AI による属性の推論** — `interview_report` は AI が「主婦」「物流業者」等の属性を
   **本人が明示していなくても推論して**保存している。この扱いに注意点はあるか
5. **個人情報を含みうる自由記述** — 「入力しないでください」と告知したうえで、
   入力された場合に自動的な検出・削除を行わない運用で問題はないか

> **相談先**: 個人情報保護委員会の相談ダイヤル（無料）でまず 2・3 を聞き、
> 1・4・5 は弁護士に回すのが実際的。
