## 0. 要約（先に読むところ）

現行のプライバシーポリシー・利用規約・インタビュー同意モーダルには、**事実と食い違う記述**と
**書かれていない重要事項**の両方がある。本文案はその両方を直す。

7. **無保証**であること（個人運営であり可用性を保証しない）
8. **AGPL §13** のソースコード提供（フッターのリンクは実装済み。規約に根拠を書く）

## 1. 事実の整理（文案の前提）

文案を書く前に、コードとスキーマから「実際に何を取得し、どこへ送り、誰が読むか」を確認した。

### 1-1. 取得しているデータ

| データ | 保存先 | 個人情報を含みうるか | 備考 |
|---|---|---|---|
| インタビューの質問・回答の**全文** | `interview_messages.content` | **含みうる**（自由記述） | role（assistant/user）と本文をそのまま保存 |
| インタビューの**AI 要約・意見・スタンス・属性推定** | `interview_report`（`summary`・`opinions`・`stance`・`role`・`role_description`・`role_title`・`scores`） | **含みうる** | AI が「主婦」「物流業者」などの属性を**推論**して保存する |
| インタビューセッション | `interview_sessions`（`user_id`・`started_at`・`rating`） | 識別子 | `user_id` は匿名認証の UUID |
| 有識者登録 | `expert_registrations`（`name`・`affiliation`・`email`） | **明確に個人情報** | 氏名・所属・メールアドレスを直接取得している |
| AI 利用ログ | `chat_usage_events`（`user_id`・`model`・トークン数・コスト） | 識別子のみ | 本文は入っていない |
| レポートへのリアクション | `report_reactions`（`user_id`・`reaction_type`） | 識別子のみ | |
| **AI チャットの会話本文** | `chat_logs`（**T5 で実装済み**。`session_id`・`page_type`・`bill_id`・`role`・`message`） | **含みうる** | 保存期間 90 日。`delete_expired_chat_logs()` で削除（**定期実行は T7 の未チェック項目**） |
| **LLM エラー時のサーバーログ** | サーバーの標準エラー出力 | **含みうる** | `handle-chat-request.ts` の `onError` が **`userText`（市民の発言そのもの）** を `console.error` に出す。T5 の設計どおりだが、これでサーバーログも個人情報を含む保管場所になった |
| 管理画面の変更履歴 | `admin_audit_logs`（`actor_email`・`actor_role`・`actor_faction_id`・`before_data`・`after_data`） | **管理画面利用者の個人情報** | T8 で追加。対象は `bills`・`bill_contents`・`faction_stances` の3テーブルのみで、**市民のインタビュー内容は対象外**。**保持期間は無期限**（削除処理を作らない方針が migration に明記されている） |

> **注意**: `expert_registrations` は同意モーダルの「個人情報の入力はお控えください」と**矛盾する**。
> 有識者登録は氏名・メールアドレスを**求める**フォームなので、
> 「AI との対話には個人情報を入力しないでほしい」と「登録フォームでは個人情報を預かる」を
> 文案では**明確に分けて**書く。

### 1-2. 外部への送信先（ここが方針 §2 の「はみ出し」）

コードを読むと、LLM への送信は **2 段構え**になっている。方針ドキュメント §2 の表は
「LLM API（OpenAI等）」としか書いていないが、実際にはその手前に **Vercel AI Gateway** が挟まる。

```
現状:   ブラウザ → 自前サーバー（日本国内） → Vercel AI Gateway（米国） → 各モデル提供事業者（米国）
決定後: ブラウザ → 自前サーバー（日本国内） → OpenAI（米国）
```

> **決定（2026-09-23）: Gateway を外し、OpenAI を直接呼ぶ**（冒頭の決定事項2）。
> 文案の送信先は **OpenAI 1社のみ**として書いた。**実施は T6 の範囲に含める。**

- 設定は `AI_GATEWAY_API_KEY`（`.env.example`）。モデル指定は `openai/gpt-4o` のような
  **Gateway 形式**（`packages/shared/src/ai/models.ts`）で、`gateway(modelId)` 経由で呼ぶ
  （`handle-chat-request.ts`・`handle-interview-chat-request.ts`）
- 現在の既定モデル: AI チャット = `openai/gpt-4o`、AI インタビュー = `openai/gpt-5-mini`
- 定数には Google（`google/gemini-3-*`）・Anthropic（`anthropic/claude-*`）も並んでおり、
  議案ごとに `interview_configs.chat_model` で上書きできる

**文案への影響**: 決定により、プライバシーポリシー第5条の送信先は **OpenAI 1社のみ**と書く。

#### T6 に引き継ぐ作業（Gateway の撤去）

T6「Vercel 依存の撤去」のやること（`GoogleAnalytics`・`@vercel/speed-insights`・
`images.remotePatterns`）には **AI Gateway が入っていない**。決定により、**T6 の範囲に足す**。

| 作業 | 内容 |
|---|---|
| モデルの呼び出し | `gateway(modelId)` → `openai(modelId)`（`@ai-sdk/openai` は既に依存にある） |
| モデル ID | `packages/shared/src/ai/models.ts` の `openai/` 接頭辞を外す。**Google・Anthropic のモデルは呼べなくなる**ので、定数から外すか、使わないことを明記する |
| 価格表 | `web/src/lib/ai/calculate-ai-cost.ts` の `modelPricing` のキーを新しい ID に合わせる |
| コスト計測 | **壊れない**。`resolveCostUsd`（`web/src/features/chat/shared/utils/cost-utils.ts`）が `gateway の値 > ローカル価格表での計算 > 0` の3段フォールバックになっているため、Gateway の値が無ければ価格表から計算する |
| 不要になるコード | `handle-chat-request.ts` の `extractGatewayCost`（`providerMetadata.gateway.cost` の読み取り） |
| 環境変数 | `AI_GATEWAY_API_KEY` → `OPENAI_API_KEY`（`.env.example` も） |
| DB | `interview_configs.chat_model` に `google/` や `anthropic/` の値が入っている行があれば OpenAI のモデルに直す |

> **注意**: モデル ID を変えると `modelPricing` に無いキーになった時点で
> `calculateUsageCostUsd` が throw する。価格表の更新を忘れないこと。

### 1-6. どの情報が個人情報にあたるか（削除依頼の範囲）

> この節は事実の整理であって、法的な判断ではない。判断が要る点は §6 の未決事項6 と
> §7 の相談項目に出す。

**なぜ削除の窓口が要るのか — 理由は2つある。**

**理由1: 窓口を示すこと自体が法律上の要求。**
個人情報保護法は、保有個人データについて、**開示・訂正・利用停止等の請求に応じる手続と
苦情の申出先を、本人が知り得る状態に置く**ことを求めている（第32条）。
削除に応じるかどうかは場合によるが、**窓口を示さないという選択肢は無い**。

なお 2017 年の改正で「取扱件数 5000 件以下は適用除外」は廃止されているため、
個人運営であっても、反復継続して行う以上は対象になる。

**理由2: この企画の設計が「同意」に依存しているから。**
[権限設計 §4](20260912_1736_管理画面ロール権限設計.md) は、インタビューの生ログを全ロールに開く理由を
「アクセス制御ではなく**市民への事前告知と同意**でカバーする設計」と書いている。
アクセス制御をかけない代わりに同意で担保するなら、**同意が撤回できないと同意の実質が失われる**。
その撤回手段が削除依頼にあたる。こちらは法律というより、設計の一貫性の問題。

#### 項目ごとの該当性と、削除依頼の必要性

| 項目 | 個人情報にあたるか | 削除依頼の必要性 |
|---|---|---|
| `expert_registrations`（氏名・所属・メール） | **確実に該当** | **最も高い**。疑いの余地なく保有個人データ |
| `admin_audit_logs.actor_email` 等 | **確実に該当**（議員・出馬者・運営者の） | **高いが、無期限保持の決定と衝突する**（§6 の未決事項6） |
| `interview_messages`（発言の全文） | **内容次第**。本人が特定できる情報を書けば該当する | **高い**。上の理由2 がここに効く |
| `interview_report`（要約・意見・属性推定） | 同上。加えて AI が「主婦」「物流業者」等の属性を**推論して**保存している | **高い**。本人が言っていない属性が付くため |
| `chat_logs`（会話本文） | 内容次第 | **低い**。90 日で自動消滅し、どれが本人のものか特定する手段も無い |
| `chat_usage_events` | `user_id` は匿名認証の UUID、本文を含まない | **ほぼ不要** |
| サーバーログ（IP＋`userText`） | 照合次第 | 個別削除ではなく**保存期間の管理**で対応（T7） |

**結論**: 削除依頼が実際に効くのは **有識者登録** と **インタビュー（生ログ・レポート）** の2つ。
文案 第9条はこの2つを念頭に書く。

## 2. 書き方の方針

1. **できないことを約束しない**。「匿名化処理を行います」「厳重なセキュリティ」のような
   検証できない約束は書かず、実際にやっていることだけを書く
2. **主語を「当団体」から個人運営者に寄せる**。`siteConfig.operator.name` は `s.takahashi` で、
   団体ではない。文案では「運営者」を使う（表記は決定事項4 のとおり `s.takahashi`）
3. **はみ出しは隠さず書く**。LLM が国外に出ることは方針 §2 で織り込み済みの例外なので、
   詫びるのではなく**線引きの理由ごと**書く。これは発信材料でもある（方針 §1-4）
4. **難しい言い回しを避ける**。市民向けのサービスなので、法律文書の体裁より読めることを優先する

### プライバシーポリシー

{siteName}（以下「本サービス」）における個人情報およびご入力いただいた内容の取り扱いについて説明します。

本サービスは、札幌市および札幌市議会の公式サービスではありません。個人が運営する非公式のサービスです。

#### 1. 運営者

本サービスは {operator} が個人として運営しています。お問い合わせ窓口は本ポリシー第10条に記載します。

#### 2. 取得する情報

本サービスは、以下の情報を取得します。

- **AI インタビューでの質問と回答の内容**（入力いただいた文章そのもの）
- **AI チャットでのやり取りの内容**（入力いただいた文章そのもの）
- AI がインタビュー内容から生成した**要約・ご意見の整理・立場や属性の推定結果**
- **有識者リストへの登録情報**（氏名、所属・肩書、メールアドレス）※ 登録された方のみ
- ブラウザに保存される**匿名の利用者識別子**（Cookie 等。氏名等とは結び付きません）
- AI 機能の**利用量の記録**（利用日時、モデル名、処理量、費用。会話の本文は含みません）
- アクセスに伴う**技術的な記録**（IP アドレス、ブラウザの種類、アクセス日時等のサーバーログ）

本サービスは、会員登録を求めません。利用者の氏名・住所・電話番号・メールアドレスは、
有識者リストへの登録を除いて取得しません。

管理画面を利用する議員・立候補予定者・運営者については、第11条に別途記載します。

> **お願い**: AI インタビューおよび AI チャットへの入力には、氏名・住所・電話番号・
> メールアドレス・勤務先が特定できる情報など、ご自身や第三者を特定できる情報を**含めないでください**。
> 入力された内容はそのまま保存され、第3条・第4条に記載する範囲で閲覧されます。
> 本サービスは、入力内容から個人情報を自動的に検出・削除・匿名化する処理を行っていません。

#### 3. 利用目的

取得した情報は、以下の目的で利用します。

- 市民の声を整理し、**札幌市議会の議員および市議会議員選挙の立候補予定者に届ける**ため

前提として、次の 2 つは性質が違う。

- **(a) 市民の意見を政策立案の参考にすること** — 議員・立候補予定者の通常の活動

さらに、本サービス自体の性質として次の論点がある。

- **(c) 個人運営のサービスが、立候補予定者に無償で市民の意見という価値あるものを提供すること**が、

  **全候補者に等しく開放しているか否か**が評価に影響しうる

| **A. 出馬者に開放しない** | インタビュー結果の閲覧は admin と議員のみ。立候補予定者ロールは作らない | 公選法の論点がほぼ消える。市民への説明が最も簡単 | 権限設計 §4 の決定（全ロールに開く）を覆す。新人候補者が市民の声に触れられず、現職に有利に働く（**プラットフォーマーとしての中立性を損なう**） |
| **B. 開放し、利用は制限しない** | 立候補予定者も生ログを閲覧でき、選挙運動への利用も制限しない | 実装が最も単純。権限設計どおり | (b)(c) のリスクを運営者が全部背負う。市民への同意文言が重くなる（「あなたの発言が選挙運動に使われます」） |

| **D. 選挙期間中は閲覧を停止** | C に加え、**告示日から投票日までは立候補予定者ロールの閲覧を停止**する | 選挙運動期間との接点を物理的に断てる | 実装が増える（期間管理）。選挙直前こそ候補者が見たい時期であり、サービスの価値を下げる |

**推奨は C。** 理由:

- 権限設計 §4 の「生ログまで全ロールに開く／アクセス制御ではなく告知と同意でカバーする」という
  決定を維持できる
- 「声を選別せず届ける場を提供するプラットフォーマー」（方針 §1-1）という立ち位置と整合する。
  A は現職に有利に働き、この立ち位置を損なう
- 市民に対して「**議員と候補者が読みます。ただし選挙の宣伝にそのまま載せることは禁じています**」
  という、短く筋の通った説明ができる

**C を採る場合の条文案:**

> #### 第X条（議員・立候補予定者による利用の制限）

>    本サービスから得た意見であることを示して言及することも、これに含みます。
> 3. 閲覧した内容を、第三者に提供・公開しないでください。
> 4. 閲覧した内容に利用者を特定できる情報が含まれていた場合、その情報を利用者への連絡、

## 7. 並行してやる人手作業: 専門家への相談

相談は**公職選挙法**と**個人情報保護法**の2本立てになる。
弁護士に相談する場合は1回でまとめて聞けるが、選管に聞けるのは公選法だけ。

### 7-A. 個人情報保護法について

§1-6・§6 の未決事項6 で出た論点。**公選法より先に片付けられる**（選管を待つ必要がない）。

1. **監査ログと削除請求**（§6 の 6-b）— 管理画面の変更履歴に実行者のメールアドレスを
   **無期限で**保存し、アカウント削除後も残す設計について、本人から削除を求められた場合に
   **応じない**ことは許されるか。目的（議案解説の変更履歴の検証可能性）の正当性と、
   アカウント発行時に告知していることは、判断にどう効くか
2. **事業者の氏名・住所の公表**（§6 の 6-c）— 個人運営の場合、第32条の公表事項を
   「求められたら回答する」形で満たせるか。サイトに本名・住所の掲載が必要か
3. **本人確認の方法** — 会員登録が無いサービスで、**結果ページの URL を知っていること**をもって
   本人からの削除依頼として扱うことに問題はないか
4. **AI による属性の推論** — `interview_report` は AI が「主婦」「物流業者」等の属性を
   **本人が明示していなくても推論して**保存している。この扱いに注意点はあるか
5. **個人情報を含みうる自由記述** — 「入力しないでください」と告知したうえで、
   入力された場合に自動的な検出・削除を行わない運用で問題はないか

> **相談先**: 個人情報保護委員会の相談ダイヤル（無料）でまず 2・3 を聞き、
> 1・4・5 は弁護士に回すのが実際的。

### 7-B. 公職選挙法について

タスク T2 の「並行でやる人手作業」。
当初は回答が出るまで T9 の「出馬者に開放する」をマージしない予定だったが、
**2026-09-24 のユーザー判断で、回答を待たずに開放する**ことにした（T9 / PR #34）。
確認は引き続き進め、**回答次第で開放の範囲や §5-3 の決定を見直す**。

> **前提が変わった点**: §5-3 で**案B（読んだ後の使い方を規約で縛らない）**を選んだため、
> 質問は「案C で足りるか」ではなく「**縛らずに開放した場合のリスク**」を聞くものに変わる。

### 相談したいこと

1. **立候補予定者が、本サービスで読んだ市民の発言を、選挙運動用のビラ・ウェブサイト・SNS に
   引用すること**について、公職選挙法上の問題はあるか。
   運営者が規約でこれを制限していない場合、**運営者側に責任が及ぶ余地はあるか**
2. 個人運営のサービスが立候補予定者に無償で管理画面を提供することが、
   **寄附または選挙運動費用**として扱われる余地はあるか。全候補者に等しく開放していれば問題ないか
3. サービス上に「立候補予定者」として氏名が並ぶことが、**事前運動**にあたる余地はあるか
4. 市民の意見（インタビュー要約）を公開することが、**特定候補者への支持・不支持の表明**と
   受け取られる場合の扱い
5. 市民から「自分の発言が候補者の選挙運動に使われた」と申し出があった場合、
   運営者が取るべき対応はあるか（削除、当該候補者のアクセス停止など）

> **回答次第では §5-3 の決定を見直す**。案B は「今は規約に書かない」という判断であって、
> 「書く必要が無いと確認できた」わけではない。
